    - `initDb()` — async wrapper
    - `getAllUsers()`, `getUserById(id)`, `createUser(name, email)`, `updateUser(id, name, email)`, `deleteUser(id)` — all async

    Implementation (per locked decisions):
    1. **DB_FILE env** (D-07): `process.env.DB_FILE ? path.resolve(...) : path.join(DATA_DIR, 'users.db')` — mirror DATA_FILE pattern, do NOT overload DATA_FILE (D-08)
    2. **initDb()** (D-04): `mkdirSync(DATA_DIR, { recursive: true })` → `new DatabaseSync(DB_FILE_PATH)` → read `schema.sql` with `readFileSync` → `db.exec(schema)`
    3. **seedIfEmpty()** (D-05): after schema, `SELECT COUNT(*) AS count FROM users`; if count === 0, INSERT John Doe and Jane Smith via prepared statements (same emails as SEED_DATA)
    4. **CRUD** (D-02, D-10): use `DatabaseSync` from `node:sqlite` ONLY — zero npm deps (SQLITE-02). All queries via `prepare()` with `?` placeholders — never interpolate user input
    5. **getAllUsers**: `SELECT id, name, email FROM users ORDER BY name` (SQL sort per RESEARCH recommendation)
    6. **createUser**: `INSERT` + return `{ id: Number(lastInsertRowid), name, email }` from `stmt.run()` return value (NOT stmt.lastInsertRowid)
    7. **updateUser**: return `null` if `changes === 0`, else updated object
    8. **deleteUser**: fetch user first; return `null` if not found; else DELETE and return deleted user
    9. Module-level `let db` handle — single connection per process
    10. Do NOT enable WAL mode (keeps single .db file for learners)
    11. Do NOT read users.json at any point (D-06)

    Export: `module.exports = { initDb, getAllUsers, getUserById, createUser, updateUser, deleteUser }`
  </action>

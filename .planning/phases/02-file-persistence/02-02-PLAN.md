ANTES (handler actual, síncrono):
```javascript
app.post('/users', (req, res) => {
  const validationError = validateUserPayload(req.body);
  if (validationError) {
    return res.status(400).json({ error: validationError });
  }
  const user = {
    id: nextUserId,
    name: req.body.name.trim(),
    email: req.body.email.trim()
  };
  nextUserId += 1;
  users.push(user);
  res.status(201).json(user);
});
```

DESPUÉS (handler async con saveUsers() y rollback):
```javascript
app.post('/users', async (req, res) => {
  const validationError = validateUserPayload(req.body);
  if (validationError) {
    return res.status(400).json({ error: validationError });
  }

  const user = {
    id: nextUserId,
    name: req.body.name.trim(),
    email: req.body.email.trim()
  };
  nextUserId += 1;
  users.push(user);

  try {
    await saveUsers();
  } catch (err) {
    users.pop();
    nextUserId -= 1;
    console.error('[error] saveUsers() falló en POST /users:', err.message);
    return res.status(500).json({ error: 'No se pudo persistir el cambio. Comprueba los permisos del archivo.' });
  }

  res.status(201).json(user);
});
```

Rollback de POST: `users.pop()` elimina el último usuario añadido; `nextUserId -= 1` devuelve el contador al valor previo.

El mensaje de error 500 debe ser exactamente: `'No se pudo persistir el cambio. Comprueba los permisos del archivo.'` (D-06 — texto educativo en español, sin variaciones).

DESPUÉS (handler async con saveUsers() y rollback por copia):
```javascript
app.put('/users/:id', async (req, res) => {
  const userId = parseUserId(req.params.id);
  if (userId === null) {
    return res.status(400).json({ error: 'El parámetro ":id" debe ser un número entero.' });
  }
  const validationError = validateUserPayload(req.body);
  if (validationError) {
    return res.status(400).json({ error: validationError });
  }
  const userIndex = findUserIndexById(userId);
  if (userIndex === -1) {
    return res.status(404).json({ error: 'Usuario no encontrado.' });
  }

  const previousUser = { ...users[userIndex] };
  users[userIndex] = {
    id: userId,
    name: req.body.name.trim(),
    email: req.body.email.trim()
  };

  try {
    await saveUsers();
  } catch (err) {
    users[userIndex] = previousUser;
    console.error('[error] saveUsers() falló en PUT /users/:id:', err.message);
    return res.status(500).json({ error: 'No se pudo persistir el cambio. Comprueba los permisos del archivo.' });
  }

  res.json(users[userIndex]);
});
```

Rollback de PUT: `const previousUser = { ...users[userIndex] }` guarda una copia superficial antes de sobrescribir; en el catch se restaura con `users[userIndex] = previousUser`.

### DELETE /users/:id

ANTES (handler actual, síncrono):
```javascript
app.delete('/users/:id', (req, res) => {
  const userId = parseUserId(req.params.id);
  if (userId === null) {
    return res.status(400).json({ error: 'El parámetro ":id" debe ser un número entero.' });
  }
  const userIndex = findUserIndexById(userId);
  if (userIndex === -1) {
    return res.status(404).json({ error: 'Usuario no encontrado.' });
  }
  const [deletedUser] = users.splice(userIndex, 1);
  res.json({
    message: 'Usuario eliminado correctamente.',
    user: deletedUser
  });
});
```

DESPUÉS (handler async con saveUsers() y rollback con splice):
```javascript
app.delete('/users/:id', async (req, res) => {
  const userId = parseUserId(req.params.id);
  if (userId === null) {
    return res.status(400).json({ error: 'El parámetro ":id" debe ser un número entero.' });
  }
  const userIndex = findUserIndexById(userId);
  if (userIndex === -1) {
    return res.status(404).json({ error: 'Usuario no encontrado.' });
  }

  const [deletedUser] = users.splice(userIndex, 1);

  try {
    await saveUsers();
  } catch (err) {
    users.splice(userIndex, 0, deletedUser);
    console.error('[error] saveUsers() falló en DELETE /users/:id:', err.message);
    return res.status(500).json({ error: 'No se pudo persistir el cambio. Comprueba los permisos del archivo.' });
  }

  res.json({ message: 'Usuario eliminado correctamente.', user: deletedUser });
});
```

Rollback de DELETE: `users.splice(userIndex, 0, deletedUser)` reinserta el usuario en su posición original. NO usar `users.push(deletedUser)` — cambiaría el orden del array (Pitfall 6 de RESEARCH.md).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cliente HTTP → Route handler | Datos de req.body (name, email) cruzan desde el cliente al proceso Node |
| Route handler → Sistema de ficheros | Mutación en memoria + escritura async a api/data/users.json |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Tampering | app.post/put/delete — rollback incompleto | mitigate | Rollback explícito en cada handler: POST→pop()+decrement, PUT→restore previousUser, DELETE→splice(index,0,user). Acceptance criteria verifican cada rollback individualmente. |
| T-02-02-02 | Denial of Service | Express 4 + async handler sin try/catch | mitigate | Cada await saveUsers() está dentro de un bloque try/catch explícito. Sin try/catch el rechazo de promesa sería huérfano en Express 4 (RESEARCH Pitfall 3), dejando al cliente sin respuesta y potencialmente terminando el proceso en Node 22. |
| T-02-02-03 | Tampering | Input — name/email no validados antes de persistir | accept | validateUserPayload() ya existente rechaza payloads inválidos con 400 antes de llegar a saveUsers(). Control preexistente, sin cambios. |
| T-02-02-04 | Elevation of Privilege | path traversal via req.params.id | accept | parseUserId() convierte el parámetro a entero con parseInt; cualquier valor no numérico devuelve null → 400. No hay rutas de archivo que dependan del parámetro :id. |
</threat_model>

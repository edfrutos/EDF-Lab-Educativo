Términos mínimos a incluir por bloque (seleccionar los más representativos del lab):

**Backend, HTTP y API** — incluir: servidor, endpoint, puerto, request / response, código HTTP, JSON, CRUD, Express, CORS, módulo.
- Entrada `servidor`: dónde vive la lógica. Ejemplo: `node api/index.js`.
- Entrada `endpoint`: ruta que la API expone. Ejemplo: `curl http://localhost:3100/users`.
- Entrada `puerto`: número que identifica el proceso. Ejemplo: `PORT=3100 npm start`.
- Entrada `request / response`: la petición y la respuesta HTTP. Ejemplo: `curl -v http://localhost:3100/health`.
- Entrada `código HTTP`: qué significa cada número (200, 201, 400, 404, 500). Ejemplo: `curl -o /dev/null -w "%{http_code}" http://localhost:3100/users`.
- Entrada `JSON`: formato de intercambio de datos. Ejemplo: bloque JSON del laboratorio.
- Entrada `CRUD`: las 4 operaciones. Ejemplo: mencionar los 4 verbos HTTP con su endpoint del lab.
- Entrada `Express`: el framework de Node.js usado. Ejemplo: snippet de `app.get('/health', ...)`.
- Entrada `CORS`: por qué el navegador bloquea peticiones entre orígenes. Enlace a docs/05-cors-explicado.md.
- Entrada `módulo`: qué es `require()` en Node.js. Ejemplo: `const app = require('./index.js')`.

**Frontend y navegador** — incluir: fetch(), DOM, origen, async / await, promesa.
- Entrada `fetch()`: la función del navegador para hacer peticiones HTTP. Ejemplo: snippet de dashboard/app.js.
- Entrada `DOM`: árbol de elementos HTML que JavaScript puede modificar. Ejemplo: `document.getElementById('...')`.
- Entrada `origen`: combinación protocolo+host+puerto. Ejemplo: `http://localhost:5173` vs `http://localhost:3100`.
- Entrada `async / await`: sintaxis para código asíncrono. Ejemplo: función fetchUsers del lab.
- Entrada `promesa`: objeto que representa un valor futuro. Ejemplo: `fetch(...).then(r => r.json())`.

**Persistencia y tests** — incluir: memoria vs disco, fixture, suite de tests, Arrange-Act-Assert, beforeEach.
- Entrada `memoria vs disco`: diferencia entre array en RAM y archivo JSON. Enlace a docs/08-memoria-vs-persistencia.md.
- Entrada `fixture`: datos de prueba controlados y predecibles. Ejemplo: bloque TEST_SEED de index.test.js.
- Entrada `suite de tests`: conjunto de tests para verificar el comportamiento. Ejemplo: `npm test`.
- Entrada `Arrange-Act-Assert`: patrón para estructurar cada test. Ejemplo: bloque describe/it del lab.
- Entrada `beforeEach`: hook que se ejecuta antes de cada test. Ejemplo: el beforeEach de index.test.js.

**Herramientas del entorno** — incluir: Node.js, npm, nodemon, curl.
- Entrada `Node.js`: entorno de ejecución de JavaScript en el servidor. Ejemplo: `node --version`.
- Entrada `npm`: gestor de paquetes de Node.js. Ejemplo: `npm install`, `npm start`, `npm test`.
- Entrada `nodemon`: herramienta que reinicia la API automáticamente al detectar cambios. Ejemplo: `npm run dev`.
- Entrada `curl`: herramienta de línea de comandos para hacer peticiones HTTP. Ejemplo: `curl http://localhost:3100/health`.

Restricciones absolutas:
- SIN frontmatter YAML (no añadir `---\ntitle: ...\n---`)
- Los ejemplos DEBEN usar localhost:3100, no URLs ficticias de internet
- Los datos de ejemplo: john@example.com, jane@example.com (coherentes con el lab)
- No usar rutas absolutas hardcodeadas a /Users/edefrutos/ en los ejemplos
- Longitud de ejemplos: 3-5 líneas máximo

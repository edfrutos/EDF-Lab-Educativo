# Milestone v2.0: Quality & CI

**Status:** ✅ SHIPPED 2026-06-15  
**Phases:** 26–29  
**Total Plans:** 8  
**Tag:** `v2.0`  
**Merge:** PR #8

## Overview

Automatizar confianza end-to-end en los tres dashboards y exigir la suite Postgres en cada PR — con material didáctico que convierte fricción real en aprendizaje.

## Phases

### Phase 26: Fundación E2E Playwright (vanilla)

**Goal:** El operador puede ejecutar localmente un smoke E2E de autenticación en el dashboard vanilla sin levantar servidores a mano.  
**Requirements:** QA-E2E-01, QA-E2E-02, QA-E2E-05, QA-CI-04  
**Plans:** 2/2 complete

- Scaffold Playwright en raíz (`e2e/`), dual `webServer`, smoke auth vanilla
- Job CI `e2e-smoke` + documentación inicial en `docs/10-tests.md`

### Phase 27: E2E multi-dashboard

**Goal:** Los tres dashboards pasan el mismo smoke de autenticación y CI ejecuta la suite completa en cada pull request.  
**Requirements:** QA-E2E-03, QA-E2E-04, QA-CI-02  
**Plans:** 2/2 complete

- Specs React (`:5174`) y Vue (`:5175`); helper `auth-smoke-flow.js`
- Quad `webServer` + tres proyectos Playwright; CI con `npm ci` en frameworks

### Phase 28: Postgres CI obligatorio

**Goal:** Ningún PR puede mergearse sin pasar la suite Postgres además de SQLite y E2E.  
**Requirements:** QA-CI-01, QA-CI-03  
**Plans:** 2/2 complete

- Job `test-postgres` (`postgres:16`, `pg_isready`, `npm run test:pg`)
- README y doc 10: matriz de tres jobs obligatorios

### Phase 29: Material didáctico Quality & CI

**Goal:** El alumno puede reproducir la puerta de calidad v2.0 en local y aprender de errores reales documentados.  
**Requirements:** DOCS-01, DOCS-02, DOCS-03  
**Plans:** 2/2 complete

- `docs/10-tests.md` ampliado (duración CI, por qué Postgres, tabla tres capas)
- Mission 16; NOTEBOOK v2.0; CHANGELOG y ruta v2.0 en índice/README

## Milestone Summary

**Key accomplishments:**

1. Playwright smoke auth en vanilla, React y Vue — login UI real, sin `AUTH_DISABLED`
2. CI en paralelo: `test-sqlite` (24) + `test-postgres` (23) + `e2e-smoke` (3 specs)
3. Helper E2E compartido y selectores estables (`#login-email`, roles en español)
4. Mission 16 + NOTEBOOK v2.0 con fricción real (selectores, webServer, Postgres local)
5. Tag `v2.0` y release GitHub publicados

**Issues resolved during milestone:**

- Playwright strict mode: `getByLabel('Email')` colisionaba con CRUD en vanilla
- `ERR_CONNECTION_REFUSED` al usar `webServer` por proyecto con workers paralelos → quad `webServer` global

**Issues deferred (post-v2.0):**

- Full CRUD E2E (QA-ADV-01)
- E2E against Postgres API (QA-ADV-03)
- Firefox/WebKit in CI (QA-ADV-04)
